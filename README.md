# 实验三 城市间交通规划与导航

实现指导书要求的最省钱出行方案自动生成系统：用有向带权图表示城市交通网络，
在公路、铁路、航空三种交通方式混搭的情况下，用 Dijkstra 算法求出两城市之间
权值最小的出行方案，并输出每一段所采用的交通方式。

## 功能

- **交通网络建模**：节点为城市，边为道路；公路、铁路、航空各用一张 `n × n` 邻接矩阵存储权值，`0` 表示该方式没有直达线路。
- **城市信息存储**：`unordered_map<string,int>` 完成城市名到编号的映射，`vector<string>` 完成编号到城市名的映射，查找平均 O(1)。
- **修改版 Dijkstra**：松弛时同时比较三种交通方式，跨方式混搭求最小总权值；`PreInfo` 数组记录“前驱节点 + 交通方式”，用栈逆转得到正向路径。
- **交互式查询**：输入起点、终点城市，输出最小权值及完整行进路线；输入 `@ @` 退出。
- **三种规划依据**：默认按费用规划；用命令行参数 `time` / `distance` 可将权值解释为时间 / 距离，分别得到时间最短、距离最短的方案。
- **规模**：城市数量动态分配，支持 20 个城市、50 条以上道路；实测 20 个城市、74 条有向道路。
- **输入校验**：节点编号越界、权值非正、起终点相同、格式错误、城市名重复等情况均有提示，不会导致程序崩溃。

## 编译

在 `transport` 目录下执行：

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
    -finput-charset=UTF-8 -fexec-charset=UTF-8 \
    src/graph.cpp src/dijkstra.cpp src/main.cpp -o transport.exe
```

VS Code 中可直接运行“Build Transport Planner (g++)”任务。

## 输入格式

程序按以下顺序交互输入。执行 `./transport.exe < tests/sample_input.txt` 可直接复现指导书中的样例：

1. **城市个数**：`6`
2. **公路权值**：每行 `点 点 权值`，以 `0 0 0` 结束
3. **铁路权值**：同上
4. **航空权值**：同上
5. **城市与节点对应关系**：共 n 行，每行 `城市 节点编号`
6. **查询**：每行两个城市，空格隔开；输入 `@ @` 退出

样例输入（指导书 6 城市图）：

```
6
0 1 5
0 2 30
0 3 35
1 2 24
1 5 10
1 4 29
2 5 17
3 0 15
4 5 3
5 4 12
5 3 8
0 0 0
... 铁路、航空权值略，完整内容见 tests/sample_input.txt ...
v0 0
v1 1
v2 2
v3 3
v4 4
v5 5
v0 v5
v0 v2
v1 v3
@ @
```

| --- | --- | --- |

按费用规划时，结果行的措辞沿用指导书运行截图中的“最短距离”。

## 时间最短 / 距离最短

图的每条边（每种交通方式）存储一个权值，由命令行参数决定其含义：

```bash
./transport.exe            # 默认按费用，输入各地之间的费用
./transport.exe time       # 按时间，输入各地之间的耗时
./transport.exe distance   # 按距离，输入各地之间的距离
```

三者共用同一套 Dijkstra 代码，只是边权含义不同；输入格式和输出路线完全一致，
结果行分别显示“最短距离”“最短时间”“最短距离”。

## 算法说明

修改版 Dijkstra 与经典算法的三处不同（对应指导书）：

1. 松弛邻居时不再只看一张权值矩阵，而是遍历公路、铁路、航空三张矩阵，取使总权值更小的那条边；
2. 前驱数组由 `int` 改为 `PreInfo` 结构体，同时记录前驱节点编号和本段所用的交通方式；
3. 求路径时从终点沿 `PreInfo` 回溯到起点，回溯过程压栈，再依次出栈得到正向路线。

复杂度：单次查询 O(V² × 3) = O(V²)（V 为城市数），空间 O(3V²)（三张邻接矩阵）。
20 个城市时矩阵仅 3 × 20 × 20 个整数，查询为毫秒级。
